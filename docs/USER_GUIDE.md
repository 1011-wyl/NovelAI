# Novel Agent 使用手册

> 适用项目版本：0.1.x  
> 最后更新：2026-10-02

Novel Agent 是一个个人使用的长篇小说创作智能体。它可以根据频道、题材、标签和核心想法生成创作方案，再逐章执行单次精简细纲、上一章正文接续、题材写法校准、必要的现实知识调研、正文写作、oh-story 去 AI 味、八维可读性审稿、Story Skills 一致性审校、修订、人物记忆更新和章节储备。

本文档面向日常使用者。接口开发说明见 [API.md](API.md)，外部服务配置说明见 [API_SETUP.md](API_SETUP.md)，系统结构说明见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 使用前须知

### 1.1 两种运行模式

| 模式 | 用途 | 是否调用外部服务 | 创作质量 |
|---|---|---|---|
| 离线模式 | 验证页面、数据库和完整工作流 | 否 | 仅用于工程演示 |
| 在线模式 | 使用已配置的大模型（DeepSeek、通义千问等 OpenAI 兼容接口）进行真实方案、规划、写作和修订 | 是 | 日常创作应使用此模式 |

离线生成器的内容是确定性的测试文本，不适合作为正式小说正文。要获得真实创作质量，需要配置可用的在线模型 API。

仓库中的 `.env.example` 使用离线模式，表示新复制项目在没有本地配置时不会调用外部服务。这只是安全初始值，不代表本机始终离线。实际运行状态以页面左下角和“系统设置”中的 LLM 状态为准。

### 1.2 当前不会自动做的事情

- 不会真实发布到番茄、起点、晋江等平台。
- 不会在没有确认创作方案时自动开始写作。
- 不会把一次性路人和临时工具人长期保存为人物档案。
- 搜索和 Embedding 没有配置时不会擅自调用外部接口。

## 2. 安装与启动

### 2.1 环境要求

- Windows 10/11。
- Python 3.11 或更高版本。
- Node.js 20 或更高版本（仅用于构建前端；日常运行不需要）。
- 推荐使用 PowerShell。

在 PowerShell 中执行：

```powershell
cd D:\NovelAgent
python -m pip install -e .
cd apps\web
npm ci
npm run build
cd ..\..
```

如果已经安装过依赖并构建过前端，可以跳过安装和构建步骤。

完整开发验证（含前端 lint、组件测试、构建、Playwright 与 Python 测试）可使用：

```powershell
.\scripts\verify-frontend.ps1
```

Playwright 会使用系统临时目录中的独立测试数据库，不会读写默认的 `data/novel_agent.db`。每条浏览器用例开始和结束时都会清理该测试库中的小说，测试服务器退出后会删除本轮临时目录，避免不同用例和不同运行相互污染。

### 2.2 启动服务

任选一种方式：

```powershell
cd D:\NovelAgent
python -m novel_agent serve
```

或：

```powershell
.\run.ps1
```

也可以双击项目根目录下的 `run.cmd`。

如果提示找不到 `apps/web/dist/index.html`，请先按 2.1 节完成 `npm run build`。

开发前端时可开两个终端：

```powershell
# 终端 1：后端 API
python -m novel_agent serve

# 终端 2：Vite 开发服务器（代理 /api 到 8000）
cd apps\web
npm run dev
```

看到下面的地址后，使用浏览器打开：

```text
http://127.0.0.1:8000
```

停止服务时，在启动服务的终端按 `Ctrl+C`。

### 2.3 页面没有显示最新修改

依次执行：

1. 在旧服务终端按 `Ctrl+C`。
2. 如修改了前端，进入 `apps/web` 执行 `npm run build`。
3. 重新运行 `python -m novel_agent serve`。
4. 在浏览器按 `Ctrl+F5` 强制刷新。

仅刷新页面不能替换已经加载到旧 Python 进程中的后端代码，也不能替换未重新构建的前端产物。

## 3. 配置在线大模型

推荐在网页里配置。打开左侧「系统设置」，在「运行能力状态」中点击「大模型 (LLM)」卡片（也可用键盘聚焦后按 Enter 或空格）。卡片会显示：

- 未配置：还没有可用的页面配置或环境变量。
- 已启用：当前新任务会使用这里显示的供应商和模型，例如 `阿里云百炼 DashScope · qwen-plus`。
- 待验证：刚改过地址、模型或密钥，还没有保存启用；保存并启用后卡片会变成已启用。生成仍会使用已保存并启用的配置，但建议再点「测试连接」确认密钥有效。
- 需要处理：密钥无效或模型不可用，点击卡片可查看安全的错误说明。
- 已停用：你在页面里点过「停用」。新任务不会调用大模型，也不会改用 `.env` 里的配置，直到再次「保存并启用」。

### 3.1 在页面中填写

1. 选择供应商：DeepSeek、阿里云百炼 DashScope、OpenAI，或自定义 OpenAI 兼容接口。
2. 系统会填入推荐的 API 地址和模型 ID，你可以改成账号实际可用的名称。
3. 在外部官网申请 API Key，粘贴到本页。输入框默认遮挡，可临时显示；密钥只发给这台电脑上的后端，接口不会再把完整密钥返回来。
4. 点「测试连接」。这只会做一次很短的连通性检查，用来确认地址、模型和密钥，不代表已经开始写小说。
5. 点「保存并启用」。密钥会写入本机凭据库，卡片变为「已启用」，并显示供应商和模型名。建议先点「测试连接」确认密钥可用；不测试也可以保存，之后新任务会使用这份配置。如果密钥无效，生成时会看到真实错误，不会悄悄改成离线成功。

编辑已有配置时，页面只显示「已保存密钥」的尾号提示。密钥框留空表示继续用原来的密钥；只有输入新内容才会替换。更改供应商、地址或模型后，抽屉会提示需要重新测试连接。点「停用」会立刻停止调用大模型（包括环境变量里的配置），直到再次保存并启用。点「清除配置」只删除本机页面保存的密钥；如果 `.env` / `.env.local` 里还有有效配置，清除后会继续使用环境变量。当前只靠环境变量、还没有页面保存记录时，也可以直接点「停用」来覆盖环境变量。自定义兼容接口在本机 `127.0.0.1` / `localhost` 可以使用 http；对外地址需要 https。

### 3.2 环境变量（兼容旧部署）

没有页面配置时，程序仍会读取 `.env` / `.env.local`。页面里保存并启用的配置优先于环境变量。若页面里是「已停用」，则不会再回退到环境变量。两者都没有、且运行模式为离线时，才使用离线演示模型。远程调用失败时会显示真实错误，不会悄悄改成离线成功。

如果还没有 `.env` 或 `.env.local`，可以复制示例文件：

```powershell
Copy-Item .env.example .env.local
```

程序会先读 `.env`，再读 `.env.local`（后者不覆盖已在环境中存在的变量）。推荐把真实密钥放在本机 `.env` / `.env.local`，不要提交到版本库。

#### DeepSeek 示例

```env
NOVEL_AGENT_MODE=online
LLM_PROVIDER=deepseek
LLM_API_KEY=填写你自己的DeepSeek密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-pro
LLM_TIMEOUT_SECONDS=120
LLM_MAX_RETRIES=2
```

也可以使用 `DEEPSEEK_API_KEY` 代替 `LLM_API_KEY`。

#### 通义千问（阿里云百炼）示例

```env
NOVEL_AGENT_MODE=online
LLM_PROVIDER=dashscope
LLM_API_KEY=填写你自己的百炼密钥
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen3.7-plus
LLM_TIMEOUT_SECONDS=180
LLM_MAX_RETRIES=2
```

说明：

- `LLM_PROVIDER` 也可写 `qwen`，默认与 `dashscope` 相同。
- 也可以使用 `DASHSCOPE_API_KEY` 代替 `LLM_API_KEY`。
- 北京地域常用 Base URL 为 `https://dashscope.aliyuncs.com/compatible-mode/v1`；国际（新加坡）为 `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`。密钥与 Base URL 必须同一地域，否则常见报错是 `invalid_api_key`。
- 若控制台提供了业务空间专属域名，把 `LLM_BASE_URL` 换成控制台给出的 OpenAI 兼容地址（以 `/compatible-mode/v1` 结尾）。

#### 其他 OpenAI 兼容接口

```env
NOVEL_AGENT_MODE=online
LLM_PROVIDER=openai-compatible
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://你的兼容网关/v1
LLM_MODEL=你的模型名
```

`LLM_MODEL` 必须填写该账号当前有权调用的模型名称。仅使用环境变量时，保存后需要重启服务。左下角显示“在线模式”，系统设置中 LLM 显示已启用，说明配置已经被识别。页面里保存的配置会立即作用于之后新启动的任务，不必为改密钥而重启，但不能让正在跑的任务中途换模型。

### 3.3 密钥安全

- 不要把密钥发到聊天记录、截图或公开仓库。
- 不要把真实密钥写进 `.env.example`、README 或源代码。
- 页面保存的密钥放在本机系统凭据存储中（Windows 凭据管理器等），数据库只保存引用和尾号提示，不保存明文。
- `.env` / `.env.local` 只保存在当前电脑。
- 如果密钥曾经公开，立即在供应商后台撤销并重新生成。
- 换电脑或重装系统时，需要重新在设置页填写密钥，或继续使用你备份的环境变量文件。
- 调用模型可能产生供应商费用，本应用不代购额度。

常见提示：

- 「API Key 无效或已失效」：核对密钥、地域和 Base URL 是否配套。
- 「当前账号无法使用该模型」：把模型 ID 改成控制台里真实开通的名称后再测试。
- 「请求过于频繁或额度受限 / 账户额度不足」：到供应商控制台查看配额后再试。
- 「连接超时 / 无法连接服务」：检查网络和 API 地址，可把超时调到 10～300 秒后重试；一次超时不会永久判配置无效。
- 「本机安全凭据存储不可用」：页面保存的密钥要写入本机凭据库，不能写进普通数据库。在项目目录执行 `python -m pip install keyring`（或重新 `python -m pip install -e .`），确认 Windows「凭据管理器」可用，然后重启服务。不要用明文文件代替。仅自动化测试可设置 `NOVEL_AGENT_SECRET_STORE=memory`。

### 3.4 模型调用发生在什么时间

在线模式下，以下操作会调用模型：

- 创建或重新生成创作方案。
- 生成一份包含冲突、选择、代价和情节点预算的章节细纲。
- 写作章节正文。
- 初稿和每次自动修订后的八维可读性审稿。
- 审核未通过后的正文修订。
- 章节完成后提取重要人物档案。
- 为旧作品重建重要人物档案。
- Story Skills 在线语义一致性审校；初稿和每次自动修订后各调用一次。
- oh-story `story-deslop` 写后润色；每个初稿调用一次。

因此，一次“生成下一章”通常仍不止一次模型请求，但默认流程已取消三案生成和独立择优，改为一次精简规划。正常通过时主要调用细纲、正文、可读性审稿和人物提取；启用 oh-story 后，每个初稿再增加一次语言润色，启用 Story Skills 后初稿和每次修订还会增加一致性审校。可读性或一致性审核发现主要问题时会触发修订和再次审校，调用次数随修订轮数增加。重建旧作品人物档案时，大约会按 READY 章节逐章调用人物提取。

## 4. 可选外部能力

### 4.1 Tavily 搜索与网页阅读

需要现实知识调研和来源核验时，在 `.env.local` 中增加：

```env
SEARCH_PROVIDER=tavily
SEARCH_API_KEY=填写你的Tavily密钥
SEARCH_BASE_URL=https://api.tavily.com
SEARCH_TIMEOUT_SECONDS=30
SEARCH_MAX_RESULTS=3
```

只有章节计划提出现实专业问题时才会触发搜索。系统会保存标题、网址、域名、摘录、可信度和交叉来源状态。

搜索失败时会使用保守写法继续生成，不会直接阻断小说生产。

### 4.2 SiliconFlow Embedding

用于从历史章节摘要和研究资料中召回语义相关内容：

```env
EMBEDDING_PROVIDER=siliconflow
EMBEDDING_API_KEY=填写你的SiliconFlow密钥
EMBEDDING_BASE_URL=https://api.siliconflow.cn/v1
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_TIMEOUT_SECONDS=60
SEMANTIC_RETRIEVAL_LIMIT=6
```

DeepSeek 密钥不能代替 Embedding 密钥。Embedding 只负责派生检索；人物状态、世界规则和时间线仍以 SQLite 中的结构化数据为准。

### 4.3 Story Skills 一致性审校

项目内置并固定了 `danjdewhurst/story-skills` 的 `revision-continuity` 与 `story-maintenance`，默认启用：

```env
STORY_SKILLS_ENABLED=true
```

它在每次章节审核时自动检查人物知识、人物状态与位置、时间和因果顺序、剧情线、伏笔、世界硬规则、人物关系以及相邻章节衔接。创作工作台的生产流程会显示 `StorySkillsAudit` 节点，系统设置会显示 `STORY_SKILLS` 的启用状态。

- 离线模式只运行本地确定性契约，不会因为 Story Skills 联网。
- 在线模式会把当前草稿和本次审校所需的正式上下文发送给已配置的 DeepSeek，并增加一次模型请求；自动修订后会再次审校。
- SQLite 始终是人物、世界规则、时间线和伏笔的权威存储。系统不会维护第二套长期 Markdown 故事库，也不会自动执行第三方 Node 脚本。
- 如果临时不需要这项审校，可在 `.env.local` 中设置 `STORY_SKILLS_ENABLED=false`，保存后重启服务。

### 4.4 oh-story 写作质量 Skill

项目固定引入 `worldwonderer/oh-story-claudecode` 的 `story-long-write` 和 `story-deslop`，默认启用：

```env
OH_STORY_ENABLED=true
```

它不会把上游文件式写作项目直接搬进 NovelAgent，而是由 Python 宿主安全调用其中与当前项目匹配的能力：

- **先定情绪，再定故事**：每章明确目标情绪、读者回报、紧张感或爽点，以及章末留下的新期待；每个情节点都必须服务于一次情绪变化。
- **更细的章节规划**：除目标、阻力、转折和钩子外，记录全书阶段、剧情单元、章节定位、主角目标和关键选择、多线推进、关系变化、信息差、禁止提前释放项，以及每个情节点的密疏强度和字数预算。
- **题材专属写法**：运行时从 32 张题材正文提示卡中只选择与当前项目最匹配的一张，例如“末世”选择“科幻末世”。题材卡只影响写作提示，不会把卡名、标签或规则写进正文。
- **写后去 AI 味**：初稿生成后调用 `story-deslop` 做一次最小范围语言编辑，保留剧情、人物、伏笔、钩子和时间线；随后本地复扫否定翻转句、模板声线、破折号、章末升华和高频套词，重大命中会进入原有自动修订循环。

创作工作台的生产流程会显示 `GenreProseCard` 和 `ProsePolish` 节点；创作方案会显示“读者契约与核心期待”；系统设置会显示 `OH_STORY` 的启用状态。

- 离线模式会加载同一套题材卡、补齐细纲字段并运行本地扫描，但正文与润色仍是确定性演示文本。
- 在线模式会把本章计划、当前草稿、选中的唯一题材卡和经过裁剪的 Skill 指南发送给已配置的 DeepSeek；每个初稿增加一次模型请求。
- SQLite 仍是项目、章节和长期记忆的唯一权威存储。上游 Node 脚本、安装命令、Hook 和自定义 Agent 不会由服务自动执行。
- 如需临时关闭，可设置 `OH_STORY_ENABLED=false` 并重启。关闭后恢复旧的章节计划、正文和基础审核流程，不执行题材卡与去 AI 味步骤。

## 5. 页面导航

打开 Novel Agent 后默认进入「我的小说」书架。电脑端左侧导航固定在窗口中，滚动右侧内容时不会一起移动。展开时可点击导航顶部右侧的收起按钮切成仅显示图标的窄栏；窄栏时点击顶部的「N」即可重新展开。手机端仍使用菜单按钮打开抽屉导航。「系统设置」固定在左侧栏最底部，不跟在其他导航项后面。主内容区铺满侧栏右侧可用宽度，底部状态条显示当前运行模式和外部能力是否启用。

| 页面 | 主要用途 |
|---|---|
| 我的小说 | 默认首页。搜索、排序、网格/列表浏览全部小说；可修改书名或删除 |
| 创作工作台 | 查看项目状态、创作方案、章节储备和生产流程；确认方案后可生成下一章 |
| 作品阅读 | 三栏阅读与修订工作台：浏览 READY 章节、编辑工作草稿、与 AI 协作改写；批准后才写入草稿，应用修订后才成为正式版本 |
| 长期记忆 | 查看重要人物、世界硬规则、时间线和研究资料；手机上在人物列表与详情之间切换 |
| 仪表盘 | 查看写作活动、LLM 调用统计与调用记录 |
| 系统设置 | 查看并配置大模型，查看搜索、Embedding、Story Skills 与 oh-story 是否启用，保存非敏感本地偏好 |

没有选中小说时，点击「创作工作台」「作品阅读」或「长期记忆」会回到书架并提示先创建或选择一本小说。项目作用域页面顶部可切换当前小说。新小说尚未确认创作方案时，「作品阅读」和「长期记忆」会返回创作工作台，不能通过直接输入地址绕过确认步骤。

## 6. 创建一本小说

### 6.0 从书架开始

1. 在「我的小说」点击「新建小说」。
2. 按三步填写：故事起点 → 创作偏好 → 连载计划与边界。
3. 点击「生成创作方案」。生成过程中按钮会锁定，请勿重复提交。
4. 成功后自动进入该小说的创作工作台，并显示一次性提示「创作方案已生成，请检查后确认」。

未提交的表单草稿会保存在本机；创建成功后自动清除。若生成过程中关闭页面，请先刷新书架确认是否已创建完成，避免重复提交。

### 6.1 选择读者频道

进入新建页面后，先选择：

- 男频：偏向目标推进、升级反馈和世界探索。
- 女频：偏向人物成长、情感因果和关系变化。

切换频道后，主类型、阅读体验、核心元素、主角设定和感情线会同步替换。标签是跨平台归纳后的创作方向，不等同于平台官方投稿分类。

### 6.2 填写创作要求

- **主类型**：小说的核心题材。
- **书名（可选）**：留空时由模型给出候选书名。
- **阅读体验**：希望读者获得的整体感受，可多选。
- **核心元素**：系统、重生、经营、快穿等故事机制，可多选。
- **主角设定**：主角的成长和行为类型，可多选。
- **核心想法**：尽量说明主角身份、起点、核心矛盾和不希望出现的捷径。
- **必须包含**：方案和正文必须持续满足的内容。
- **希望包含**：优先考虑但不是硬性要求的内容。
- **明确不要**：禁止出现的题材、桥段或结局。
- **感情线**：无感情线、1v1、单女主等。
- **单章目标字数**：允许 800–8000 字。
- **每日章节**：更新计划参考值。
- **储备安全线**：希望维持的 READY 章节数量。

网页端创建的小说必须先确认创作方案。生成完成后，页面只显示方案审阅、修改、重做、版本比较和删除操作；今日完成、章节储备、生产流程、长期记忆与作品阅读会在确认方案后开放。

### 6.3 生成方案

点击“生成创作方案”后，系统会生成：

- 候选书名与正式书名。
- 故事简介和目标读者。
- 核心卖点。
- 主角和主要冲突。
- 重要人物初始档案。
- 世界硬规则。
- 开篇三章方向。
- 总章节数、分卷数和更新计划。
- 文风规则。

成功后会进入该小说的方案审阅页。检查无误并点击「确认创作方案」后，同一页面会开放完整创作工作台。也可随时从书架点击卡片或「继续创作」回到当前阶段。

### 6.4 在书架修改书名或删除

- **修改书名**：在书籍菜单中选择「修改书名」。只改标题，不同步改变项目状态、确认状态或章节；书架标题与方案中的正式书名会保持一致。
- **删除未确认空草稿**：普通二次确认即可。
- **删除已确认或已有章节的作品**：必须完整输入当前书名才能删除，此操作不可撤销。

## 7. 方案不满意时怎么处理

在点击“确认创作方案”之前，可以：

### 7.1 手工修改

点击“修改方案”，直接修改书名、简介、主角、冲突、世界规则、开篇三章、文风和连载计划，然后保存为新版本。

### 7.2 按意见重新生成

在反馈框中说明问题，例如：

```text
书名不要太直白；主角不要一开始就无敌；第一章更快进入冲突；减少系统提示。
```

可以只勾选“书名”“故事核心”“主角”“世界规则”“开篇三章”“文风”或“连载计划”。不勾选模块时会整体优化。

模型偶尔可能返回空内容、无效 JSON 或缺少方案字段。系统会自动追加一次格式修复请求；修复成功后才保存新版本，仍不合格则保留原方案并显示错误。自动修复会额外产生一次模型调用和相应费用，请不要连续重复点击。

### 7.3 比较与恢复版本

每次修改或重新生成都会保存新版本。通过左右两个版本下拉框进行比较，也可以把旧版本恢复为一个新的当前版本。

### 7.4 确认后的限制

点击“确认创作方案”后，方案进入正式写作状态，不能再按草稿方式直接修改。确认前应重点检查：

- 主角姓名和背景是否分开且正确。
- 主要冲突能否支撑长篇连载。
- 读者契约和核心期待是否符合你想提供的阅读体验。
- 世界规则是否互相矛盾。
- 排除项是否明确。
- 开篇三章是否符合预期节奏。

尚未确认且没有章节的草稿可以直接删除。已经确认或已有章节的作品也可以删除，但必须在提示框中完整输入当前书名。删除会永久移除本地数据库中的方案、章节、人物、时间线、研究和版本数据，不能撤销；操作前应先按第 13.2 节备份。

## 8. 生成和管理章节

### 8.1 生成下一章

创作方案确认后，点击“生成下一章”。系统依次执行：

1. 加载最近章节摘要、时间线、世界规则和人物档案。
2. 召回相关语义记忆（启用 Embedding 时）。
3. 选择与项目题材匹配的唯一正文提示卡。
4. 基于目标情绪和读者回报，生成一份包含明确冲突、关键选择、可见代价、转折和情节点字数预算的细纲。
5. 判断细纲是否需要现实知识调研。
6. 写作正文；第二章起会向作者提供上一章末尾约 1800 字，要求直接接续未完成动作、问题、在场人物和叙事语气，不复述上一章。
7. 使用 `story-deslop` 去 AI 味并运行本地复扫；润色结果没有改善自然度或增加严重问题时保留原稿。
8. 执行八维可读性审稿，分别检查开篇钩子、场景因果、冲突升级、人物主动性、对话辨识度、具体呈现、读者回报和章末钩子。
9. 执行基础文本审核、去 AI 味复扫和 Story Skills 一致性审校。
10. 任一可读性维度低于门槛或出现主要/阻断问题时自动修订，并重新执行全部审核。
11. 生成摘要和人物变更。
12. 原子提交正文、时间线和长期记忆。
13. 将章节标记为 READY。

创作工作台会显示 `Plan` 和 `ReadabilityReview` 节点。`ReadabilityReview` 会保存八项分数。第 1 章会绑定创作方案里的第一条开篇锚点，不会去“承接上一章”；人物档案里尚未发生的未来关系也不会当成开篇已经成立的事实。普通质量问题未通过时，章节保留为 `FAILED`，项目继续保持可用。第 1 章仍失败时，按钮会写成“重新生成第 1 章”，不会误显示成已经可以写下一章。长度、语言类问题可以沿用细纲重写；开篇错位、人物状态或连续性错误需要重新规划。审稿模型自己返回的 `PASS`、`REVISE` 或 `HUMAN_REQUIRED` 不会覆盖统一分数判定；`HUMAN_REQUIRED` 项目状态只保留给质量评分之外的工作流异常恢复场景。

批量生成或储备补充遇到第一个 `FAILED` 章节会立即停止，不会在同一任务中反复调用模型。检查失败节点后，由你决定是否再次生成。

不要在模型请求进行时关闭启动服务的终端。

### 8.2 暂停与继续

点击“暂停”后，项目进入 `PAUSED`，不能生成新章节。点击“继续”恢复为 `ACTIVE`。

暂停不会删除已有方案、章节或人物数据。

### 8.3 章节状态

| 状态 | 含义 |
|---|---|
| PLANNED | 单次细纲已保存目标情绪、关键选择、代价与情节点预算 |
| RESEARCHING | 正在或准备调研 |
| WRITING | 正在生成正文 |
| REVIEWING | 正在执行八维可读性、基础文本、去 AI 味复扫和 Story Skills 一致性审校 |
| REVISING | 正在自动修订 |
| READY | 正式正文已经安全提交，可以阅读 |
| FAILED | 本次草稿未通过质量门槛或生成失败，保留检查点；可在阅读页改草稿并重新送审，不能直接当成正式章节 |

草稿版本不会更新正式人物记忆。只有章节通过审核成为 READY 时，正文、人物状态和时间线才会在同一事务中提交。

### 8.4 打回章节重做

在未通过审核的章节上可以看到分数、主要问题和建议动作：

- **查看审校意见**：阅读本次未通过的原因。
- **重新规划并重写**：丢弃旧细纲，按开篇锚点重新规划后再写。
- **沿用细纲重写**：只在细纲正确、问题主要是字数或语言时出现。开篇错位、人物初态、连续性或世界规则问题不能沿用旧细纲，系统会拒绝“只改文字、不重规划”。
- **检查并修复开篇数据**：仅当第 1 章仍失败、还没有正式章节，并且系统判断人物初态可能被未来设定污染时出现。确认前会说明影响范围（人物关系从哪改到哪、第 1 章状态、会保存和清理的内容），并先做可回退快照。修复时会清掉这次错误第一章带进来的网页研究资料，避免它们再次混进新的第 1 章。

普通“重做”仍会重置该章及后续章节。填写的修改意见只在新细纲成功保存后使用一次。归档项目不能直接重做；暂停项目重做后仍保持暂停，需要点击“继续”。

旧项目不会在启动时被自动改写。只有你在工作台明确确认“修复开篇数据”后才会调整人物初态。刷新或重新打开工作台后，只要还没有新的正式章节，仍可看到并使用“回退开篇修复”。若修复后已经生成正式章节，回退会被安全阻止，以免冲掉后来的正文。

## 9. 阅读与修订工作台

进入“作品阅读”：

1. 左侧栏顶部用书籍卡片选择器切换小说项目（点击当前书名展开封面列表）。
2. 左侧选择章节（可筛选 READY / 其他）；未提交草稿会显示圆点。
3. 中间阅读或编辑当前章标题与正文；`READY` 和未通过审核的 `FAILED` 章节都可以改工作草稿。
4. 右侧可切换顾问 / 共创 / 编辑模式，与 AI 对话；编辑模式产生的改写需**批准**后才进入工作草稿。宽屏点击「关闭」会收起右侧助手栏，正文区变宽，不会留下空白列。
5. `READY` 章节点击「应用修订」把工作草稿提交为新的正式版本。`FAILED` 章节不能使用「应用修订」，只能「重新送审」。重新送审会走和自动连载相同的完整质量检查：没通过时页面仍显示“未通过审核”，你刚改的草稿还在，可以继续改；通过后才变成正式章节。若工作区能力信息缺失，编辑、AI 和送审会暂时全部禁用，请刷新页面或确认后端版本。

作品阅读页为全幅三栏工作台，不显示顶栏标题；书籍选择器位于左侧栏顶部。电脑端章节栏、正文栏和 AI 助手栏采用固定的响应式比例，不提供拖动分隔线；关闭助手后只保留章节栏和正文栏。中间栏字数统计贴在正文区底部，右侧 AI 输入框贴在助手栏底部。页面中的多行文本框不显示右下角缩放手柄，尺寸由页面布局或内容区域控制。顶栏服务状态、正文栏的「版本」「放弃草稿」「应用修订 / 重新送审」、助手栏的「新建」「关闭」以及对话里的「回滚到这里」，都和「顾问 / 共创 / 编辑」使用同一套描边按钮。选中正文后需**右键**才会在指针旁弹出润色 / 精简 / 扩写等快捷菜单。未通过审核的章节会在正文上方显示恢复横幅，可返回工作台重新规划，或继续改草稿后重新送审。

### 9.1 工作草稿与自动保存

- 编辑内容先保存在工作草稿中，不会立刻改写正式章节。
- 标题和正文约 800ms 自动保存；也可用 `Ctrl/Cmd+S` 立即保存。
- 「放弃草稿」会恢复到当前正式正文。
- 版本历史可把旧正式版或重置快照「恢复为工作草稿」，仍需再次应用修订才会成为正式版。

### 9.2 AI 助手边界

- AI **不能**直接改写正式章节。
- 顾问 / 共创只给建议；编辑模式生成待批准修改，显示差异后由你批准或拒绝。
- 批准只写入工作草稿；「应用修订」才会生成新正式版本并更新记忆。

### 9.3 应用修订与后续章节

- 无后续章节时，确认后提交新版本。
- 若后面还有章节，会提示将安全重置的编号范围；旧内容保留在版本历史（`RESET_ARCHIVE`），不会像「重做」那样物理删除版本。
- 左侧控制台的「重做」按钮行为不变：仍会清理该章及后续版本，与「应用修订」不同。

章节状态、标题和正文采用左对齐排版。目录中的版本号是当前正式正文版本。

## 10. 重要人物档案

### 10.1 哪些人物会建档

只为需要长期追踪的人物建立档案：

- 主角和直接决定主线走向的核心人物。
- 会反复登场的重要盟友、竞争者和反派。
- 掌握关键资源或信息的人物。
- 与主角形成持续关系的人物。
- 行动会造成跨章节影响的人物。

一次性具名路人、传话者和只完成单一功能的临时工具人不建立长期档案。

### 10.2 查看档案

进入“长期记忆”：

- 电脑端左侧显示人物目录，右侧只显示当前选中人物的详情。
- 默认选中主角。
- 点击其他人物，只切换右侧档案，不刷新整页。
- 手机端先显示人物列表，点击后进入详情，可以返回人物列表。

档案内容包括人物背景、性格、长期目标、当前目标、最近结果、所在位置、已知信息、关系和最近出场章节。

### 10.3 重建重要人物档案

旧作品或人物数据不完整时，点击“重建重要人物档案”。系统会扫描全部 READY 章节：

- 补建遗漏的重要人物。
- 更新已有重要人物。
- 清理不再符合重要人物标准的档案。
- 保留主角和创作方案中的主要人物。

在线模式下会逐章调用模型。开始前页面会要求确认。如果任一章节提取失败，系统不会执行清理，以避免误删档案。

## 11. 世界、时间线与研究资料

### 11.1 世界硬规则

显示不可随意改变的设定，例如能力来源、资源限制、感染规则和人物知识边界。锁定规则会参与后续章节规划和审核。

### 11.2 时间线

每个 READY 章节提交一条带章节证据的正式事件。草稿和失败章节不会污染正式时间线。

### 11.3 研究资料

启用 Tavily 后，章节调研的来源、摘要、可信度和交叉核验状态会显示在这里。

页面显示的“语义索引”数量来自章节摘要与研究资料。语义检索不会替代人物和世界规则的权威存储。

## 12. 仪表盘

侧栏「仪表盘」提供三个页签，数据全部来自本地 SQLite，刷新后保持不变。

### 12.1 写作

- 年度创作热力日历：按本地时区统计每天非空白正文字符数；绿色越深表示字数越多。
- 右侧指标：总创作天数、连续创作天数、总创作章节、总创作字数。
- 下方可按项目和日期筛选最近区间的四张图：写作字数变化、累计创作字数、来源贡献占比、创作活跃日分布。
- 字数口径：章节正文中的**非空白字符数**。
- 来源含义：`agent` 为智能体正式提交；`user` 为将来用户编辑；`import` 为历史回填或导入。启用本统计前已有正文的章节，会在数据库升级时按当前正文一次性记为「导入」，无法还原真实逐日过程。

### 12.2 LLM 统计

- 四项指标：调用次数、Token 消耗、平均响应时间、首字响应时间。
- 下方六张图展示调用趋势、模型分布、消耗趋势、响应时间和项目消耗等。
- 当前 DeepSeek 为非流式调用，首字响应时间显示为 `—`，不会用总响应时间冒充。
- 第一版不提供筛选条，展示全量历史。

### 12.3 调用记录

- 可按项目、模型、提供商、类型、状态、日期范围筛选，并搜索模型、操作或错误信息。
- 桌面宽屏使用表格，较窄桌面、平板和手机会自动改为分组记录卡片；筛选项按可用宽度换行，不需要横向拖动页面或筛选框。
- 记录支持排序与分页；字段包括时间、项目、模型、操作、用时、首字、输入（缓存）、输出、状态。
- 页签、筛选输入和分页按钮保持适合触屏点击的尺寸。
- 记录不包含 API Key、完整提示词或完整模型输出。

## 13. 系统设置

「系统设置」固定在左侧栏最底部，可以：

- 点击「大模型 (LLM)」卡片配置供应商、API 地址、模型 ID 和 API Key，并测试连接、保存启用、停用或清除。
- 查看搜索、Embedding、Story Skills、oh-story 等其他运行能力是否启用。
- 保存默认每日章节数、默认储备安全线、预算提醒额度和调试偏好。

页面不会显示或返回明文 API Key。预算提醒属于本地偏好，不应视为供应商侧的强制消费上限。Token 与调用明细请到「仪表盘」查看。

## 14. 数据库、备份与恢复

### 14.1 默认位置

默认数据库：

```text
D:\NovelAgent\data\novel_agent.db
```

可以在 `.env.local` 中修改：

```env
NOVEL_AGENT_DATABASE=data/novel_agent.db
```

SQLite 数据库按 `project_id` 隔离不同小说。人物、章节、方案版本、时间线、研究资料和语义索引都与所属项目关联。

### 14.2 安全备份

备份前先停止服务，避免只复制主文件而遗漏 WAL 中尚未合并的数据：

```powershell
cd D:\NovelAgent
Copy-Item .\data\novel_agent.db .\data\backup_novel_agent_20260718.db
```

建议在以下操作前备份：

- 批量重建旧书人物档案。
- 打回已有章节重做。
- 删除已经确认或已有章节的作品。
- 手工操作数据库。
- 升级数据库结构。
- 大量生成章节。

### 14.3 恢复备份

1. 停止服务。
2. 先保留当前数据库副本。
3. 把备份文件复制为配置中的数据库文件名。
4. 重新启动服务并检查项目、章节和人物数量。

不要在服务运行时直接替换数据库文件。

### 14.4 SQLite 的容量边界

SQLite 适合当前个人单机使用。小说和章节数量增加时，正文、版本和语义向量会让数据库持续增长。建议：

- 定期备份。
- 不要同时启动多个写入同一数据库的服务。
- 定期检查 `data` 目录空间。
- 进入多人使用、持续高并发或长期无人值守阶段后，再迁移 PostgreSQL、对象存储和任务队列。

## 16. 常见问题

### 15.1 `项目当前状态不可自动写作：HUMAN_REQUIRED`

表示模型明确报告了需要人工处理的阻断问题，或这是旧版本留下的异常状态。普通可读性分数未达标不会再把项目置为此状态。

处理顺序：

1. 查看创作工作台中的失败节点和问题信息。
2. 如果是旧版本留下的 `REVIEW_RETRY_EXHAUSTED`，更新并重启后再次点击“生成下一章”会自动恢复，并沿用原细纲定向重写；也可以点击“修复并恢复”。
3. 若恢复按钮仍报错，保留数据库和失败章节，不要反复生成。
4. 检查人物姓名、正文是否缺少主角、禁止项和目标字数。

当前自动恢复只覆盖系统明确识别的已知安全场景，不会对所有失败强行恢复。

### 15.2 `创作方案尚未确认`

返回创作工作台，检查方案后点击“确认创作方案”。

### 15.3 `项目已暂停`

点击“继续”后再生成章节。

### 15.4 缺少 LLM API Key

检查 `.env` 或 `.env.local`：

```env
NOVEL_AGENT_MODE=online
LLM_PROVIDER=dashscope
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen3.7-plus
```

修改配置后必须重启服务。

### 15.5 401 或鉴权失败

- 检查密钥是否完整，前后是否有多余空格。
- 检查密钥是否被撤销。
- 检查 Base URL 和模型名称是否属于同一供应商、同一地域（通义千问尤其常见：北京 Key 不能配国际域名）。
- 页面若仍显示“DeepSeek …”而你实际用的是千问，请确认已重启到支持 `dashscope` / `qwen` / `openai-compatible` 的版本。

### 15.6 429 或限流

等待一段时间后重试，并检查供应商的额度、并发限制和账户余额。不要连续快速点击“生成下一章”。

### 15.7 请求超时

可以适当提高：

```env
LLM_TIMEOUT_SECONDS=180
```

章节目标字数越大，规划、写作和修订耗时越长。

### 15.8 重做创作方案时返回 502

先查看页面显示的具体错误。系统会对无效 JSON 和缺少字段自动修复一次；若仍返回 502，原方案不会被覆盖。请检查 DeepSeek 余额、模型权限和服务状态，稍后再试，并确认 `.env.local` 中的 `LLM_MODEL` 是账号有权调用的模型。修改配置或安装本次修复后必须重启服务。

### 15.9 新功能或新样式没有出现

停止旧服务、重新启动，并按 `Ctrl+F5`。如果 8000 端口仍被旧进程占用，应先关闭原来的 Python 服务窗口。

### 15.10 SQLite 工具提示缺少驱动

这是数据库查看工具缺少 SQLite JDBC 驱动，不代表数据库损坏。安装工具提示的 SQLite 驱动后再测试连接；数据库文件仍然是 `data/novel_agent.db`。

### 15.11 Story Skills 启动失败或未显示

- 确认 `vendor/story-skills/skills/revision-continuity/SKILL.md` 和 `vendor/story-skills/skills/story-maintenance/SKILL.md` 存在。
- 修改 `STORY_SKILLS_ENABLED` 后必须重启服务。
- 系统设置中 `STORY_SKILLS` 显示“已启用”才表示运行时加载成功。
- 固定 Skill 文件缺失时，启用状态下程序会拒绝启动，避免无提示地跳过一致性审校。需要临时排障时可以设置 `STORY_SKILLS_ENABLED=false`，但生成的章节将不经过该 Skill。

### 15.12 oh-story 启动失败、没有题材卡或没有去 AI 味

- 确认 `vendor/oh-story/skills/story-long-write/SKILL.md`、`vendor/oh-story/skills/story-deslop/SKILL.md` 和 `vendor/oh-story/skills/story-long-write/references/genre-prose-cards/` 存在。
- 修改 `OH_STORY_ENABLED` 后必须重启服务；系统设置中 `OH_STORY` 显示“已启用”才表示加载成功。
- 在生产流程中检查是否出现 `GenreProseCard` 和 `ProsePolish`。没有完全匹配的题材时会使用通用或相近题材卡，不会把所有卡一起加载。
- 在线模式下去 AI 味需要额外一次 DeepSeek 请求。调用失败时本次章节工作流会失败并保留检查点，不会把未完成润色的草稿提交为 READY。
- 固定文件缺失时程序会拒绝启动，避免无提示跳过。临时排障可以设置 `OH_STORY_ENABLED=false`，但会同时关闭情绪细纲增强、题材卡和去 AI 味。

## 17. 成本与安全建议

- 先用短篇测试项目验证模型和提示词，再开始长篇连载。
- 方案不满意时应在确认前修改，避免生成无用章节。
- 批量重建人物档案前先备份，并注意逐章模型调用成本。
- 每章默认只生成一份精简细纲，不再调用三案生成和独立择优；规划接收紧凑 JSON 和上一章末尾 1200 字，正文接收完整细纲和上一章末尾 1800 字。
- DeepSeek V4 只在创作方案和章节规划阶段启用思考模式；正文、修订、审稿和人物提取使用非思考模式，减少额外推理 Token。
- 普通质量问题耗尽自动修订次数后会保留 `FAILED` 草稿。长度或语言问题再次生成可沿用细纲；开篇错位或人物初态问题会重新规划。也可以在阅读页修改草稿后重新送审。
- 可读性审稿只接收与阅读体验有关的方案、人物、文风和约束字段，以及上一章末尾 800 字；不会改变正文目标字数、人物档案、世界规则或正式记忆。
- 八维可读性审稿会在初稿和每次自动修订后各增加一次 DeepSeek 请求，并发送当前草稿、所选细纲、创作方案和上一章末尾摘录。
- Story Skills 在线审校会在初稿和每次自动修订后增加一次 DeepSeek 请求；问题越多，修订和复审成本越高。
- oh-story 在线去 AI 味会为每个初稿增加一次 DeepSeek 请求，并发送当前草稿、细纲、选中的题材卡和裁剪后的润色规则；批量生成前应先用一章评估质量与成本。
- Tavily 和 Embedding 是独立服务，需要各自的密钥和额度。
- 真实平台发布目前没有实现，`MockPublisher` 不会把正文发到平台。
- 涉及医疗、法律、武器、化学等高风险现实知识时，应人工核验来源与正文。
- 服务默认只监听 `127.0.0.1`，并且浏览器跨域访问只允许同源页面。不要把服务直接暴露到公网；需要远程访问时应在前面增加身份认证和 HTTPS。

### 16.1 长期记忆预算

以下变量控制每次发给模型的长期记忆上下文：

```env
MEMORY_BUDGET_TOKENS=6000
MEMORY_CHARACTER_GAP=10
MEMORY_WORLD_FACT_GAP=20
MEMORY_TIMELINE_GAP=15
MEMORY_RESEARCH_GAP=5
MEMORY_RESEARCH_RELIABILITY=0.5
```

章节间隔值用于确定同类信息的优先顺序，不会从 SQLite 删除旧数据。主角档案和锁定世界规则始终保留；研究资料只有已交叉核验或可信度达到阈值时才会进入常规写作上下文。

章节版本保护：普通生成失败或质量重试会把本次结果保存为新的草稿版本，旧草稿不会被覆盖或删除。章节列表和阅读页显示的是最新草稿；对 `FAILED` 章节打开阅读页时，可以展开“历史草稿”查看之前的版本。只有明确点击“重做”才会按操作提示清理该章及后续章节的版本，执行前请先备份数据库。

章节正文生成器和审稿器共用同一份质量契约。**唯一通过条件**是加权综合质量分 **严格大于 60**（`60.0` 分本身不算通过，页面会显示一位小数以免四舍五入误解）。写作时会尽量往 85 分以上努力，但这不是第二套门槛。八维可读性（开篇钩子、场景因果、冲突升级、人物能动性、对话声口、具体描写、读者回报、结尾钩子）仍会打分并列出问题，用于解释扣分和指导自动修订；单项 75 分、平均 82 分、`MAJOR`/`BLOCKER`，以及审稿模型自己建议的结论，**都不再单独决定是否通过**。在工作台编辑草稿后重新送审时也使用同一条规则，不存在另一套人工送审门槛。

页面会显示「综合质量分 x.x / 通过条件 > 60.0」、每轮候选分数，以及「最终采用：x.x 分（第 N 版）」。不要把分数轨迹里的最后一个数字当成最终采用版本。

字数口径为：**标点符号计入，空格、换行和明确的「第 X 章」标题行不计**。阅读页底部、顶部字数状态和后端审核使用同一口径；编辑草稿时，顶部与底部都会按当前正文实时更新。默认允许目标字数上下各浮动约 500 字：目标 3000 字时，2500～3500 字视为达标；目标 2200 字时，1700～2700 字视为达标。只要实际字数落在这个范围内，长度检查就会通过，不会因为字数去卡质量审核。首稿提示会要求模型先按场景分配篇幅，输出前按该范围内部复核；之后的语言润色如果会使正文离开范围，不会覆盖原稿。

若首稿仍偏短，系统会先定向补写再复检，**不会把字数不足显示成质量失败**；补写次数与质量修订次数分开计算。补写时模型只返回按实际缺口计算的新增片段，程序会保留原文并将片段插入结尾钩子之前，不允许补写结果比原稿更短。补写耗尽后会提示实际字数和目标范围，质量分显示为「未审核」而不是 `0.0` 分，因为此时还没有进入质量审核。请在阅读页补足后再送审。

阅读页顶部的失败提示默认只显示一行状态、关键数据和「详情」入口，不再挤占正文区域；需要时展开查看审核轨迹和恢复操作。工作台「章节储备」最多显示最近 5 章，失败章节默认只显示原因摘要，具体操作收进「处理」中，列表不再使用内部滚动框。

默认 `MAX_REVISION_ATTEMPTS=2` 表示：1 次首稿 + 最多 2 次自动质量修订。设为 `0` 时只审首稿、不自动修订。合法范围是 0～5。自动修订只会在当前最佳稿上定向改低分部分，并始终把最佳正文与该版本自己的分数、问题和证据绑定保存：如果出现 `91 → 61 → 77` 这样的轨迹，最终采用仍是 91 分那一版，也不会拿 61 或 77 分稿的问题去错误修改 91 分稿。连续无进展或正文完全不变时会提前停止。只有最终通过才会写入正式章节和记忆。

因此一次“生成下一章”可能调用多次模型（写作、去 AI 味、字数补写、每次审核、每次修订，以及可能的重新规划），成本会高于单次生成。工作台会显示质量检查次数、分数轨迹、选中版本和字数范围。

`FAILED` 后可以：重新规划并重写、在服务端允许时沿用细纲重写，或编辑草稿后重新送审。重新送审只会审核你当前编辑的草稿，不会静默改写正文。质量分不超过 60 时，不能用“接受当前版本并继续”绕过通过线。正文被截断、为空或含排除项属于生成/技术问题，也不会当成普通质量失败来“接受通过”。

`LLM_REASONING_BUDGET_FACTOR` 控制模型最大输出预算倍率，程序会限制在 `1.0` 到 `4.0`。提高倍率可能减少结构化输出被截断的概率，但也会增加耗时和费用。正文一旦被供应商标记为长度截断，系统会拒绝提交半成品。
